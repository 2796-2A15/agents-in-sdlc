Space Quiz を GitHub Pages に公開して、誰でもアクセスできる場所を用意します。Copilot はワークフローを準備し、公開を案内できますが、変更を確認し、サイトが公開されたことを確かめる責任はユーザーにあります。

このレッスンでは、次のことを行います。

- Copilot に GitHub Pages へのデプロイを構成するよう依頼します。
- マージする前にワークフローとプル リクエストを確認します。
- デプロイの状況を確認し、公開されたサイトを検証します。

## シナリオ

Space Quiz はすでに GitHub リポジトリにありますが、簡単に試せる場所がまだありません。単一ファイルのサイトを GitHub Pages で公開すると、サーバーやランタイム依存関係を追加せずに、公開 URL からアクセスできるようになります。

## Copilot にサイトのデプロイを依頼する

`space-quiz` の Copilot app セッションで、次のプロンプトを送信します。

```plaintext
このリポジトリで GitHub Pages を有効にしてください。必要に応じて Web サイトをビルドし、GitHub Pages にデプロイする GitHub Actions ワークフローを作成してください。README がまだない場合は、アプリの説明とローカルでの実行方法を記載した README を追加してください。これらの変更を含むプル リクエストを作成し、必須のチェックに合格したらマージしてください。デプロイが成功するまで監視し、成功したら公開された Web サイトの最終 URL を報告してください。Pages の有効化やマージに必要な権限がない場合は、何を承認または実行する必要があるかを正確に教えてください。サイトが公開されるまで成功したと報告しないでください。
```

> [!WARNING]
> このプロンプトは、エージェントにプル リクエストの作成とマージ、およびリポジトリの Pages 設定の変更を依頼します。続行する前に、差分、デプロイ権限、GitHub の承認要求を確認してください。

## ワークフローを確認してデプロイを検証する

1. リポジトリに README がまだない場合に限り、README が追加されていることを確認します。
2. ワークフローのビルドとデプロイの手順を含め、プル リクエストの変更を確認します。
3. 必須のプル リクエスト チェックに合格した後にのみマージします。
4. GitHub Actions のデプロイ実行が成功するまで確認します。
5. 報告された URL を開き、Space Quiz が表示されることを確認します。

エージェントが Pages を有効にできない場合やプル リクエストをマージできない場合は、提示された具体的な手順に従います。デプロイが成功し、実際にサイトが表示されるまで、タスクを完了したと見なさないでください。
